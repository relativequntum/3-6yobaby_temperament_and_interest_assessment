# 问卷蓝图｜3-6岁幼儿发展优势与兴趣画像测评

> 版本 1.0.0 ｜ 日期 2026-06-02 ｜ 语言 简体中文 ｜ 适用月龄 36-72 个月
> 本文件是**给人读**的蓝图。机读单一事实源是 `docs/item-bank.json`（HTML 渲染与未来 skill 计分均依赖它）。**两者如有出入，以 JSON 为准。**
> 工具定位（贯穿全卷的铁律）：非诊断、非筛查、非天赋鉴定；做**个体内（ipsative）相对比较**，不报人群百分位、不下临床标签；主要照看人单人家长报告；按出生年月分 3-4 / 4-5 / 5-6 三段自适应。
> 方法学准则（贴在最前）：**锚定行为、不比别家、个体内看强弱、用锚点语义说话、对乱答标注而非删除、对担忧温和建议求助、对结果始终留一句免责。**

## 1. 身份与同意（每人必经，先于所有 section）

- **知情同意页**（`consent_text`）：含「这是什么 / 这不是什么（非诊断声明）/ 用途说明 / 数据说明」四块，须勾选同意后方可进入。同意书文本版本由事实源 `item-bank.json` 顶层 `consent_version`（当前 `"1.0"`）登记，导出 JSON 的 `consent.consent_version` 取自此字段；题库版本由 `instrument.item_bank_version`（当前 `"1.0.0"`）登记，导出 JSON 的 `instrument.item_bank_version` 取自此字段。**这两个字段以 `item-bank.json` 为单一事实源**，HTML 内联块须与之保持一致。
- **识别字段**（`identity_fields`）：
  1. 出生年月（month，必填）— 决定 age_band 与锚点。
  2. 性别（select，必填，去刻板化：女孩/男孩/不便填写；明示不与同性别同龄人比较、不改变评分）。
  3. 昵称（text，选填，报告中称呼孩子）。
  4. 填写人与孩子关系（select，必填：妈妈/爸爸/祖辈/其他主要照看人）。
  5. 每日相处时长（select，必填：<1h / 1-3h / 3-6h / >6h）— 用于数据质量加权与免责措辞。
  6. child_id（auto，系统本地生成，关联同一孩子多次填写，不含明文个人身份信息）。
- **超龄提示**（`out_of_range_notice`）：出生月龄 <36 或 >72 时显示，允许继续但提示锚点不完全贴合。

## 3. 自适应分段逻辑说明

1. **入口**：家长填写出生年月 → 系统按 `age_bands` 计算月龄：36-47→`3-4`，48-59→`4-5`，60-72→`5-6`。<36 或 >72 显示 `out_of_range_notice`，允许继续但提示锚点不完全贴合。
2. **抽题**：对每道评分题，仅当当前 age_band ∈ 该题 `age_bands` 时呈现。标「全」的题三段都看；标具体段的题（如 TMP-07/18、SEL-12/15/16、DEV-03/10/11/14、INT-15、LRN-03/08/13/14）按龄启用。FAM 13 题、OPEN 3 题三段都看。
3. **每人实际题量**：3-4 段 63 评分题、4-5 段 76、5-6 段 77（加 FAM 13＋OPEN 3）。低龄段题量更少，符合简报 07「低龄家长更易疲劳、需控总长」的要求。（3-4 段被排除的 14 道按龄题：TMP-07/18、SEL-12/15/16、DEV-03/10/11/14、INT-15、LRN-03/08/13/14；77−14=63。）
4. **锚点切换**：题干**不变**，仅 `anchors_by_band` 中对应本龄段的行为例子变化（DEV 全部、TMP/SEL/INT/LRN/FAM 中标注的发展类题）。`anchors_by_band` 为 `null` 的题为纯风格/兴趣题，三段共用同一参照。
5. **三段可比性**：因子维度跨段一致、仅锚点切换，可纵向追踪同一孩子在三段间的画像变化（凭 child_id）。

## 4. 计分将如何在 skill 侧进行（概述，规则不在本卷实现）

> 本蓝图与 JSON **不做计分**；计分在未来的 skill 侧依据导出 JSON（见 `docs/json-schema.md`）与 item-bank 进行。约束如下：

1. **反向题翻转**：`reverse:true` 的题先做 `6 − raw_value`，与正向题同向后再汇总。
2. **子维度均分**：各子维度（按 §2 归并后的报告侧子维度）取其**本龄段启用题**的均值，得 1-5 分；避免不同段题量不等导致偏差。
   - **低龄段（3-4）子维度塌题降级**：因部分子维度的题为 4-5/5-6 专属，自适应到 3-4 段后会塌成 1-2 题，具体为：**LRN「面对挫折的恢复」=1 题（仅 LRN-12）、LRN「主动性与自我驱动」=1 题（仅 LRN-06）、SEL「共情与亲社会」=2 题（SEL-13,14）、INT 各 B 层品质信号子维度=1-2 题**。对这些「3-4 段题数 ≤2」的子维度，skill 侧**必须降低解读强度**（措辞从「相对突出/相对待加强」弱化为「就这一两点观察看…」），**不得据单题对该子维度下强断言**，并在该维度旁标注「本龄段题目较少，仅供参考」。是否在 3-4 段为这些子维度补全段正向题以消除塌题，列为 §7 待用户拍板项。
3. **个体内中心化（抑制光环效应）**：对该作答者全部领域均分求个人总均值，用「子维度分 − 个人总均值」得**个体内相对分**——这是 ipsative 的核心，削弱「整体好感把所有维度一起抬高」。
4. **只报相对强弱与排序**：不报百分位、不报 T 分、不设临床切分点；解读用锚点语义（「更多落在『经常』一档」）＋个体内位置（「相对突出」），**从不出现「超过 X% 的孩子」**。
5. **INT 两层**：A 层 8 领域做个体内横向排序（最被吸引/较少被吸引）；B 层 4 品质信号判断偏好「成色」；二者不混合求和。
6. **DEV ipsative**：5 领域分在孩子内部排序呈现「相对靠前/相对待加强」，**不判定达标/落后**；触发担忧时温和引导专业评估。
7. **FAM 独立成块**：要求性×回应性两维生成养育方式温和提示；屏幕/睡眠对照 WHO/AAP/AASM 给「绿色/可优化」两档建议；**不并入孩子优势分**。
8. **数据质量（预留）**：skill 侧据导出 JSON 的 `meta.quality` 标签（straightlining、作答过快、缺答、社会赞许/光环疑似、熟悉度低、近期特殊情况）**自动降级报告强度、加重免责措辞**，标注而非删除（Ward & Meade 2023）。注意检测题/红旗规则（简报 07 的 MEAS-B/E）本卷**未内置题目**，留作 skill 侧或后续版本扩展。
9. **红旗与转介**：保守触发——某发展领域原始锚点长期停在最低档、且熟悉度高/近期无特殊情况时，给一条温和非评判提示，始终以「可以问问专业人士」结尾，绝不出现诊断词。
10. **跨节自控构念共享方差**：TMP「抑制控制」(16,17,18) 与 SEL「行为与冲动控制」(04,05,06) 在内容上高度重叠（如 TMP-17「不可碰的东西忍不住去碰」≈ SEL-04「说停能停下」的反面）。二者分属「努力控制」与「行为调节」两个报告构念，但**测的是同一底层能力、共享方差**。skill 侧报告时**应合并叙述或择一呈现这条自控线索，不得把二者同时列为「独立优势」与「独立弱项」**，以免给家长「自控既是强项又是弱项」的割裂结论。
11. **成对正反题的呈现与一致性**：本卷存在若干「同子维度、一正一反」的成对题（如 INT-12 vs INT-13、SEL-08 vs SEL-09、INT-10 vs INT-11、LRN-01 vs LRN-02）。渲染侧**不应让成对正反题在同屏相邻出现**（降低家长 acquiescence/对半填答）；skill 侧可用成对正反题的应答方向是否冲突作为 `meta.quality.inconsistency_flag` 的判据之一（标注而非删除）。

## 6. 供用户逐题增删改的清单格式

```
[题干] <完整中文题干>

[量表] freq5 / like5 / single / multi / text / month
[选项] （single/multi 必填，列 v+label；freq5/like5 用标准锚点可写"标准"）
[反向] 是 / 否
[按龄锚点] 3-4: …｜4-5: …｜5-6: …（无则写 null）
[出处key] 如 Rothbart2001
[改动理由] <为何增删改，便于评审与版本留痕>
```

**改动校验清单（每次改完自查）**：
- [ ] 评分题总量仍在 70-85（当前 77）。

## 7. 关键设计取舍（需用户拍板）

详见三份交付物末尾摘要。核心几条：
1. **评分题 77 题**偏问卷上限，低龄家长可能疲劳——是否进一步删减（如砍掉部分 4-5/5-6 专属题或 INT 领域题）。
2. **未内置注意检测题/红旗转介题**（简报 07 的 MEAS-B/E）——留给 skill 侧，还是要在本卷加 1-2 道指导性应答题。
3. **TMP/INT 子维度归并**（7 维、双层）使部分「JSON 原子 subscale」单题——是否接受这种「报告侧子维度≥3、原子 subscale 可<3」的折中。
4. **FAM 是否完全不计分**：当前完全独立，仅生成建议；是否需要把养育方式两维做成可视化「画像」。
5. **child_id 生成与本地存储口径**：哈希字段构成、是否需要去标识化合规复核。**当前实现 `genChildId` 在种子中混入 `Date.now()+Math.random()`，因此同一孩子重填会生成不同 child_id**，这与 `json-schema.md` 第 37 行「关联同一孩子多次填写」的意图相悖。两种口径需用户拍板：(a) 去掉随机/时间、改为「出生月+昵称」确定性派生（可跨次关联，但同设备上两个「出生月+昵称」相同的孩子会撞 id）；(b) 维持现状随机派生（不可跨次自动关联，靠用户自行管理）。在用户定夺前代码保持现状。
